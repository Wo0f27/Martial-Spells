The former AR0 same-tick reading is explicitly superseded in `ARCHERS_RANGER_SPELL_PORT.md`.

The only spell ID remains `martial_spells:barrage`. `BarrageSpell` now exposes Ranger/Martial, max level 1, Rare/tier-three presentation, zero Iron's mana, `LONG` ten-tick cast and ten-second base cooldown. Iron's owns cast state/UI; no arrow is fired by `onServerCastTick`. Successful `onCast` launches index 0 and, only after that succeeds, schedules indexes 1/2 through the existing `RangerTickScheduler` at +2/+4. The pending jobs capture the level/dimension and caster UUID plus each launch index. They resolve the current server player at execution and skip a logged-out, removed, dead, or other-dimension caster. The source callback only checks its captured shooter for `isAlive()`; explicit same-dimension/online checks are a narrow target safety translation to avoid spawning into the old world with a player who moved or logged out. Pending callbacks are memory-only and discarded on server stop. Four-tick jobs have no cross-restart persistence.

## Old → new behavior and saved levels

The old 2/3/3/4/5 level-scaled custom-arrow volley, four-tick shot interval after preparation, 0.5–1.0 damage multipliers, six-second cooldown immunity, no-ammo custom arrows and bespoke trail are retired. The new sequence is exactly three attempted **critical** physical shots at 0/2/4 ticks, each velocity 3.15, multiplier 0.75, follow-up divergence 5. An interrupted cast emits no arrow; a successful cast whose first physical load fails emits none. The first successful arrow creates both later jobs. A failed second load does not prevent the third job from independently checking newly available ammo.

Iron's 3.16.3 `SpellData` constructor stores supplied levels without clamping. The Barrage-only constructor mixin converts old level 2–5 `SpellData` to level 1 when bindings, spellbooks, packets or saved data materialize it. New saves write level 1 on their next normal serialization. `BarrageSpell.getMaxLevel`, `getMinRarity`, and `getSpellCooldown` override potentially stale persisted pre-AR3 server config values, fixing max level 1, Rare and base 200 ticks for UI/server calculations. No ID alias or bulk NBT rewrite is needed. The developer confirmed the old-level normalization and resulting level-one behavior at runtime.

## Ammunition and physical arrow order

Every `launch` calls `ArchersPhysicalArrow.findAmmunition` again using the current main-hand-first classified bow/crossbow. It accepts an actual `ArrowItem` stack, so normal, spectral, tipped and compatible arrow subclasses keep their projectile type. One item is removed for each physical launch before spawn. Creative and plain-arrow Infinity pay no item and set creative-only pickup; Infinity does not make tipped/spectral arrows free. With 3/2/1 ammo and no inventory change, 3/2/1 arrows spawn; zero at release spawns none. Ammo added/removed between deadlines affects those later launches. The target uses vanilla `Player.getProjectile` inventory lookup. Spell Engine's optional quiver-container lookup is not a target-stack dependency; a container that does not expose ammo through vanilla/Forge projectile lookup remains an integration boundary.

The physical-arrow pipeline is: `ArrowItem.createArrow` (and bow `customArrow`) → vanilla-relevant bow Power/Punch/Flame or crossbow Piercing → Spell Engine-style critical flag/crossbow hit sound/shot marker → one old-RWA configured-damage ratio → one Barrage 0.75 multiplier → look-vector launch at 3.15 with independent first-zero/follow-up-five random divergence → `addFreshEntity` → Apothic's normal join-event Arrow Damage and Arrow Velocity exactly once → vanilla `AbstractArrow` impact damage, random critical bonus, defenses and piercing. The source `ArrowHelper.createArrow` sets critical and crossbow-style projectile state even for bow-held spell arrows; the target helper follows that physical-arrow presentation while retaining bow Power/Punch/Flame per the frozen AR1 target contract. The target does not multiply Martial Power, nominal P, Iron's spell power or Apothic Arrow Damage itself. RWA normal bow/crossbow firing mixins do not run for this independently constructed spell arrow. `ArchersPhysicalArrow.launch` now uses the source current-look vector without the movement inherited by `shootFromRotation`.

## Impact, Power Shot, piercing and persistence

Each arrow gets saved Ranger metadata: eligible physical shot, Barrage identity, iframe bypass and neutral `extraPierceTargets=0`. The accepted Power Shot join handler evaluates each **actual spawned** arrow once. Thus a three-arrow volley can spend three stash charges at 0/2/4; a missing later arrow spends none. The shared actual-hit wrapper saves the target's previous iframe value, clears it only during that arrow's hurt call and restores it in `finally`; Power Shot transfer and Barrage metadata coexist. Forge-cancelled projectile impacts do not enter the arrow's entity-hurt call. The source `knockback=0.5` is a multiplier on ordinary damage-time knockback, not an integer Punch level: a target-scoped `LivingKnockBackEvent` adjustment halves strength only within the Barrage arrow's hurt call. Vanilla Punch afterward stays at its authored integer amount.

No Barrage bonus pierce is added. Crossbow Piercing supplies the baseline byte level; the neutral AR1 `extraPierceTargets` integer remains zero. Future Strider +1 means adding one to baseline pierce (baseline zero → level one → two distinct entity hits), bounded by byte 127, without set detection here. Vanilla saves arrow type, damage/critical and PierceLevel, while Forge persistent data saves Ranger iframe/Barrage/Power Shot transfer/extra-target metadata. Vanilla's already-hit entity ID set is runtime-only and resets on arrow reload, matching the source's limited hit-history persistence; test a saved piercing arrow near a target. No volley job is saved across restart. Old in-flight `martial_spells:barrage_arrow` entities from pre-AR3 chunk saves will no longer resolve because that obsolete entity registration is removed; they are transient migration loss, not spellbook/ID loss.

## Cooldown and presentation

The Barrage-only six-second `SpellCooldownAddedEvent.Pre` override is removed. Iron's applies ordinary cooldown reduction to Barrage's fixed 200-tick base, including normal UI/server calculation. Source haste and Iron's reduction are semantic analogues, not numerically equal. Cast start plays the exact frozen `archers:bow_pull` asset under the Martial namespace. Existing client bow/crossbow pose support now follows the full ten-tick draw, then releases that pose at cast completion. The source's `spell_engine:archery_pull`/`archery_release` Emotecraft clips have no direct Player Animator runtime equivalent here; the developer accepted the held-weapon pose as the target-side visual translation. Each physical release plays Spell Engine's crossbow-shot sound with index-specific pitch. The exact frozen Barrage icon replaces the old local icon. Ammo-created arrows render normally; the obsolete custom arrow, renderer, trail particle, registration, impact event and eight trail sprites are removed. No bespoke source Barrage projectile model/trail exists.

## Rain of Arrows

`spells/RainOfArrowsSpell.java` registers `martial_spells:rain_of_arrows` as a Ranger Martial, level-one, zero-mana, tier-four/Epic LONG cast of ten ticks with base cooldown 15 seconds and ordinary Iron's reduction. The server maintains the spell's sticky AIM candidate during cast. A current visible living target replaces the candidate; a previous entity is retained only while present and visible. Successful release captures that entity UUID, or a block-hit/far-range location if none is selected. The first meteor anchors to the entity's current position; the 20 later launches resolve **the same UUID** again, using its current position when available. An unloaded/removed target leaves the last accessible anchor; there is no retargeting. Location-only casts keep one fixed anchor. The spell requires the established supported ranged weapon; it consumes no ammunition.

`NominalPhysicalRangedPower.get(player)` is sampled **once at successful release**, matching Spell Engine's `ImpactContext` capture before deliveries. The value is saved in pending jobs and projectiles; weapon changes after release do not recalculate existing Rain damage. `combat/RainOfArrowsPending.java` fires index 0 immediately and saves indexes 1–20 with deadlines `release+5, +10, …, +100` world ticks. Each due callback resolves the original caster UUID in its `ServerLevel`; death, logout, removal or dimension departure cancels remaining launches. Every delayed launch samples an independent uniform angle on the fixed radius-two ring. Saved per-dimension job data contains caster UUID, target UUID or location, last anchor, sampled power, next index and absolute deadline. Reload continues from that index and never restarts index 0. Overdue saved launches are processed one per server tick until caught up; that catch-up behavior is a deliberate reload-robustness translation of source memory-only callbacks.

`entity/RainMeteorProjectile.java` is a tracked, saved non-`AbstractArrow` FALL entity. It spawns anchor+10Y with initial downward speed 1.5, no gravity or drag. Index zero can follow its captured entity at the source default one-degree turn cap; later ring meteors have no followed target. Ordinary block/entity ray collisions do not stop FALL. It impacts after the 9.8-block distance threshold, with the source age safeguard at 1200 ticks. The optional Spell Engine reverse-collision interface has no corresponding target-stack implementation, so that unusual early termination remains a documented integration difference. Its save includes owner, followed target, sampled power and traveled distance. If the current chunk is unavailable or owner is gone, the projectile is discarded.

Each impact uses radius 1.5, source-style harmful relation exclusions and block visibility, `0.4 × sampled nominal P` damage and source fractional knockback `0.25 × SpellImpacts` default strength `0.4` via `LivingEntity.knockback`. It does not enter the physical-arrow RWA/Apothic join pipeline. The impact center is one block above the projectile position, as in Spell Engine's area impact helper. No Martial Power, Iron's spell power or bow enchantment is multiplied.

## Magic Arrow

`spells/RangerMagicArrowSpell.java` registers the distinct `martial_spells:magic_arrow` as a level-one, zero-mana, tier-four/Epic Ranger Martial with eight-second base cooldown and ordinary Iron's reduction. It opts into the existing `ReleaseChargedTechnique` Iron's release bridge. The source reference is `L=round(20/castHaste)` ticks; target Iron's Cast Time Reduction is translated to effective haste so its existing cast UI can show the charge. The server clamps `r=elapsed/L` to `[0,1]` with the source LINEAR curve. Release below `r=0.2` delegates to normal cancellation: no projectile, cooldown or item charge. Valid input release fires once, pays the normal cooldown and one spell-item cost. Overholding leaves r at one. Interruption does not fire. The `RELEASE_CHARGE` map carries only the release ratio through the synchronous cast call; authoritative long-lived projectile state is saved on the entity. The source's Spell Power haste and target Iron's Cast Time Reduction need not have numerical equality.

The source cost ID is specifically `minecraft:arrow`. The start and valid-release checks require one plain arrow in player inventory; valid release shrinks one, except creative or selected ranged weapon Infinity. Tipped/spectral arrows do not satisfy this spell-item cost, which differs from Barrage's physical-ammo loader. Charge fizzle and interrupted casts spend none. Power is sampled once at successful release, before the spawned projectile can encounter another target. The projectile keeps that sampled P, r, and `16+48r` range; weapon swaps do not alter existing damage. It launches at 1.5 and can initially follow an acquired entity UUID. Losing that entity stops homing without choosing a replacement.

Exact target Iron's 3.16.3 `MagicManager.lambda$tick$0` bytecode was also checked: its LONG branch skips automatic spell completion while `ServerPlayer.isUsingItem()` is true; `MagicData.handleCastDuration` clamps the remaining duration to zero, leaving a full charge held until item release. The opted-in `IronsReleaseUsingHelperMixin` then calls this spell's release handler. The same LONG behavior underlies the accepted Warrior charged techniques. No broad Iron's cast hook is needed.

`entity/RangerMagicArrowProjectile.java` is a tracked, saved non-`AbstractArrow` projectile. Server tick checks range/age/chunk/owner, performs the movement-vector collision raycast, applies any valid hit, turns toward the followed entity by at most two **degrees** per tick, then moves. It has no gravity or drag. A block hit discards it; irrelevant entities pass through. Each successful Spell Engine-style impact records the target UUID and cannot impact that target twice during the same flight, including after save/reload. Failed/irrelevant candidates are not recorded. The integer pierce reserve starts at 99,999, decrements after successful distinct-target continuation, and never enters vanilla's byte-sized arrow PierceLevel. The source's tiny post-hit velocity adjustment is reproduced. Range exhaustion, age above 1200, missing owner and unavailable current chunk discard the projectile.

The projectile saves owner UUID, followed UUID, sampled P, r, total range, traveled distance, remaining pierce and successful-target UUIDs, plus inherited projectile motion/NBT. This intentionally improves source reload robustness; a reload cannot reset its range or hit set, restore pierce, or duplicate ammo cost. A hit deals `1.2 × sampled nominal P × r` through the spell damage source and applies source `2 × r × 0.4` knockback with the target entity API. No AbstractArrow, Martial Power or second Apothic arrow join multiplier is involved.
